# independent-intelij-ai-plugin Changelog

## [Unreleased]
### Fixed
- A tool call that returned more than the output limit allows no longer takes the rest of its round down with it. A response can ask for six tools at once, and the first oversized result used to end the round on the spot: every call after it was answered with "this tool never ran" without being run, so approving the withheld output got you one result and five holes. All six now run — an oversized result is one call's problem and says nothing about the five beside it, which the user asked for and which may be the ones that mattered. The turn still stops once the round is done, because what to do about the withheld output is the user's decision, and each oversized call is now offered separately
- Conversations long enough to place a second cache breakpoint no longer fail outright with `a ttl='1h' cache_control block must not come after a ttl='5m' cache_control block`. The API reads a request as `tools`, then `system`, then `messages`, and rejects it if a longer TTL turns up after a shorter one — and the older of the two message breakpoints was deliberately kept for five minutes against the tail's hour, on the reasoning that it is superseded within the same turn and an hour's write price is wasted on it. That is the forbidden arrangement exactly, so every turn deep enough to place both marks failed, and what failed was the whole request rather than just the caching. The hour has moved to the older of the two marks instead, with five minutes on the tail behind it — which satisfies the rule and is also where the hour was worth more: the older mark covers the conversation up to roughly fifteen content blocks back, which in a grown chat is nearly all of it and the part that no longer changes, so a reply that takes ten minutes to write still reads that back at the cache rate and pays full price only for the tail. The tail mark is read by the next request of the same agentic loop, seconds away, and is superseded by the one that request places, so five minutes was always ample for it. Until a conversation is deep enough for a second mark to be placed at all its only message mark is the five-minute one — which is the point at which the conversation is smallest and the tool schemas and system prompt are the bulk of the request, and those keep their hour throughout
- Stopping a turn no longer saves the conversation part-way through an iteration. A chat saved at that moment held tool calls with no results, which the API rejects outright, so reopening it produced a conversation that could not be continued at all. Such a history is now also repaired when sent, so chats already saved in that state work again

### Changed
- Withheld tool output is approved from a button on the card that produced it — **Approve output**, with the token count in its tooltip — instead of a single "Continue with the edited output" link under the transcript. The link could not survive a round with more than one oversized call, since nothing about it said which output it meant. **Edit** beside it opens the output in the editor as before, and Approve then sends whatever was left in the file, so trimming a 40,000-token `find_in_files` down to the part that mattered is the same two steps it was. The file is written but no longer opened by itself: several oversized calls in one round meant several editor tabs nobody asked for. A **Continue** button appears next to **Export MD** in the reply's footer once a turn has stopped this way, and sends the conversation on — approvals spliced in, and the withheld notes standing where nothing was approved, which is what asks the model to narrow those calls itself. Both offers are withdrawn the moment the conversation is sent: after that the notes have gone to the provider and been cached, and replacing what one of them stands for would be rewriting a block that has already been over the wire. They are not saved with the chat, so reopening a conversation does not bring back an offer to splice output into a turn it has long since moved past
- The usage database is configured in `independent-ai-plugin-settings.json` too, in a `usage-database` section beside the providers — `{"url": "jdbc:mysql://localhost:3306/ai_usage?user=root&password=${env:MYSQL_PASSWORD}", "enabled": true}` — instead of in a field and a checkbox on the settings page. It names a server that belongs to the project rather than to the IDE, so it now travels with the project and is one file to copy between machines rather than a URL to retype into a dialog; a JDBC URL is also the kind of thing that is pasted rather than typed. `enabled` is what the checkbox was: it stops the writing without losing the URL, which is what a server that is down for the afternoon needs. An absent section means nothing is recorded, so a file written before this existed keeps working and simply records nothing. Settings | Tools | AICodingAgent | Logging now displays what the file says — unexpanded, so a `${env:NAME}` password stays a name — and **Test Connection** runs against the file as it stands; **Edit File** and **Reload File** in the Provider group above are how it is changed and re-read, and **Fill In Defaults** carries the section through the rewrite rather than dropping it. **An existing URL has to be moved out of the settings XML into the file by hand**: `usageDatabaseUrl` and `logUsageToDatabase` are ignored from here on, and reading them as a fallback would have left two places answering the same question
- Providers are configured in `independent-ai-plugin-settings.json` in the project root instead of field by field on the settings page. The file holds an array of configurations — `name`, `model`, `url`, `token`, `header-type`, `protocol`, `thinking`, `effort`, `max-tokens` and `context-window`, plus `anthropic-version` and `extra-headers` under `additional-customizations` — and Settings | Tools | AICodingAgent now picks between them by name from a dropdown, with a summary of what the selection sends and a warning if it cannot work. Everything after `token` is optional: the header and protocol are read off the URL, and thinking defaults to what the protocol can honestly carry. The file is written with three worked examples (Anthropic, OpenAI Responses, local Ollama) the first time a project is opened, and is never rewritten afterwards. A `token` starting with `$` names an environment variable, `$AI_API_KEY` as before; anything else is the token itself, which is what a local server wanting a placeholder needs. A **Fill In Defaults** button rewrites the file with every optional field written out at the value it is already running on, which is how a file written before a field existed gets that field back. **Existing setups need their model, URL, token header and token budgets moving into the file** — the settings page keeps only Tool calls per message, which guards the agent loop rather than describing the model, and `AI_API_URL` no longer overrides a selected entry's URL. It now says where requests go only when there is no usable file: replacing one entry's URL left that entry's protocol, token header and token describing a provider the URL no longer pointed at, which the plugin refuses to send rather than treating as an override
- Tool descriptions are about 40% shorter. They are re-sent on every request, so the wording was costing roughly 1,400 tokens a turn to say things the model did not need told twice

### Added
- **Tools | Remove Javadoc Comments**, which strips the documentation comments out of a project in one pass — Javadoc in Java, KDoc in Kotlin, and the same `/**` form wherever else the IDE parses it. Line comments and plain block comments are left where they are: this removes documentation, not commented-out code. A dialog first, because the whole project is a lot to delete on one click: it takes every Javadoc comment or only the empty stubs, scopes the run to the project view's selection when there is one, and has a report-only box that counts what would go and changes nothing. Comments are found through the PSI rather than by searching the text, so a `/**` inside a string literal is never one of them, and a comment sitting alone on its lines takes those lines with it rather than leaving a blank indented gap. The sweep scans on a background thread and writes in a single command, so however many files it touched, one Undo takes all of it back; a file that changed between the scan and the write is left alone and named in the summary balloon. It is a user action rather than a model tool — nothing here is offered to the agent
- The tool calls one model response asked for are drawn boxed together inside the reply's bubble — a box inside a box, with `3 tool calls` along the top of it. A response can ask for several tools at once and the agent runs all of them before sending anything back, so a turn that made nine calls used to be nine identical cards in a column with nothing on screen saying whether that was one round trip or nine. That distinction is what a turn costs: each round re-sends the whole conversation, so three rounds of three is roughly three times the input of one round of nine, and it is also the difference between a model working in parallel and one feeling its way a step at a time. The grouping is by the request the calls came back from rather than by "however many arrived in a row", which is what makes it right in the case that matters — a response asking for tools without saying anything first leaves nothing between its calls and the previous request's. Thinking summaries and compaction notes borrow the same card shape but are not tool calls, so they stay outside the box. The grouping is saved with the chat and comes back with it; chats saved before this existed have no request recorded against their rows and replay ungrouped, which is how they were drawn when they were written
- A `model_tool_calls` table beside `model_requests`, one row per tool call, keyed back to the `request_id` of the response that asked for it with `ON DELETE CASCADE` — so clearing out old requests takes their calls with them. Each row holds the tool's name, its arguments as a `JSON` column, what it returned as `MEDIUMTEXT`, how it ended (`OK`, `FAILED`, `CANCELLED`, `TOO_LARGE`), how long it took, its place in the round it belonged to, and JTokkit's estimate of what the arguments and the output count in tokens. The bodies in `model_requests` already contain the same calls, but only as JSON inside two columns: what a row and a foreign key buy is that `GROUP BY tool_name` becomes a query — which tool is slowest, which one fails most often, whose output is eating the context window, which is the question behind **Tokens per tool result**. The token counts are what the call will cost to *carry* from the next request on, not what anything was billed at; the billed figures stay `model_requests`' own token columns, which the provider reports. A result over a million characters is truncated with a note saying how much was dropped, since a single statement past MySQL's `max_allowed_packet` fails the write rather than shortening it, and the token count is taken before the truncation so the figure is still the real one. A row whose request never reached the server — dropped while the database was unreachable — is refused by the foreign key rather than inventing a request that no row describes. The table is created on the next connection, so nothing needs dropping, and **Test Connection** reports how many calls it holds
- `INTELIJ_AI_SETTINGS`, an environment variable naming the configuration file, so it does not have to be `independent-ai-plugin-settings.json` in the project root. Set it to a path and that file is read instead, by every project the IDE opens — which is what a set of providers naming real endpoints wants, since the project-root file is in version control and is one copy per project to keep in step. A directory is taken as the directory the file is in, so `~/.config` and `~/.config/independent-ai-plugin-settings.json` are the same instruction; `~` is your home directory, and a relative path resolves against wherever the IDE was started, so make it absolute. While it is set the file is **only ever read**: no starter file is written at that path or in the project root, and **Fill In Defaults** refuses rather than reformatting a file that belongs to you and may be shared by every project on the machine (**Edit File** still opens it). If nothing is at that path the plugin does not start — the tool window opens on the error with the path on it, an error balloon says the same when the project opens, and the side-chat button is hidden. It does not fall back to the project file or to the built-in Anthropic default, because a variable naming a file is a statement about which provider to use and quietly using a different one is worse than refusing; a missing project-root file still gets the three worked examples as before. The variable is read on each use but the tool window is built once, so changing it takes effect on the next IDE start
- What each reply cost, in small grey text along the bottom of the model's bubble — `≈ $0.0675`, with a tooltip naming the model and how many requests went into it. Per reply rather than per request, since a turn is as many requests as it takes tool calls and five figures under one answer would be five ways of not answering the question. The number climbs while a long tool loop is still running, so an expensive turn is visible as it happens rather than afterwards. Four decimals because a single reply is routinely worth less than a cent, and anything below the fourth decimal reads `<$0.0001` rather than rounding down to `$0.0000` — too small to show and free are different claims. It is saved with the chat, so a conversation reopened from the history comes back with its costs; chats saved before this existed come back without them, which is not recoverable after the fact
- A `cost_usd` column on `model_requests` holding that same estimate, from the same function on the same token counts, so what was shown and what was kept cannot drift apart. `SUM(cost_usd) GROUP BY conversation_id` is then the query that answers which chats are expensive — tokens alone cannot, since a hundred thousand cache reads on Haiku and ten thousand output tokens on Opus are the same order of magnitude as counts and nowhere near it as money. Rates are list prices kept in `ModelPricing.kt` (Opus 5, Opus 4.6, Haiku 4.5, GPT-5.6 Sol and Luna), matched loosely enough that a dated snapshot, a gateway prefix or a `4.5`/`4-5` spelling all price correctly. They live in the plugin rather than in a table on the server because the chat window shows the figure whether or not a database is configured, and one source used twice cannot disagree with itself. It is an estimate at those rates and **not a bill**: a price the provider changes changes nothing until that file is edited, and anything charged outside the four token counts is not in it. A model with no price — a local one, or one newer than the plugin — shows nothing under the reply and records NULL rather than zero, so `AVG` skips it and `WHERE cost_usd IS NULL` finds what is missing; the first such request also puts a line in `idea.log` naming the models that are priced. A table created before this column existed has it added on the next connection, so nothing needs dropping, and **Test Connection** now reports the total cost recorded
- Provider and model dropdowns above the chat transcript, **per conversation**. The first lists the entries in `independent-ai-plugin-settings.json` by name; the second lists that entry's `models` — a new field holding every model the provider can be asked for, so switching model within a provider is one more line rather than a whole second configuration. Both are saved with the chat and restored with it, so a chat reopened from the history comes back on what it was actually sent to and two chats can be on different providers at once; a chat saved before this existed comes back on the default, since what it ran on was never recorded. Changing either takes effect from the next message with the conversation so far carried over, and updates the default a new chat starts on so the next one carries on rather than snapping back. The settings page now sets that default rather than the current chat. A refresh button beside the dropdowns re-reads the file. `models` is optional: an entry with only a `model` offers a list of one, and an entry with only `models` takes its first as the default
- Every request and response is written out as a formatted JSON file, under `log/independent-ai-plugin/exchanges/<conversation-id>/<request-id>/` — `request.json` and `response.json` per exchange, one directory per chat. Each file holds the body that went over the wire and nothing else, at the top level, so `jq` and a diff work on it directly. The same bodies are in `model-traffic.0.log`, but one line each and interleaved with every other chat's, which is fine for reading the last request and useless for comparing the fourth tool-call iteration of yesterday's chat against the third. A request that never came back has no body, so its `response.json` holds the error instead. Nothing here is rotated or pruned: it grows roughly by the size of the conversation per request, so an afternoon of agentic work is tens of megabytes, and the directory is yours to empty
- Usage is recorded to a MySQL server, **replacing `model-usage.csv`**. Set the JDBC URL under Settings | Tools | AICodingAgent | Logging — `jdbc:mysql://localhost:3306/ai_usage?user=root&password=${env:MYSQL_PASSWORD}` — and the database and its `model_requests` table are created if they are not already there, so the URL may name a database that does not exist yet. Write `${env:NAME}` for the password; the field is stored in plain text. Empty URL means nothing is recorded, which is the default. A **Test Connection** button connects once, sets the schema up and reports the server version and row count. One row per request: when it was sent, which conversation, which provider, model and URL, the status code, how long it took, the error if it never came back, the input, cache-write, cache-read and output token counts with the cache hit rate, and the request and response bodies as `JSON` columns — so `request_body->>'$.model'` is a column expression rather than a file to open. The bodies make the table grow by roughly the size of the conversation per request; they are still written under `exchanges/` as well, which is the copy to diff, since MySQL normalises a `JSON` value on the way in and returns the same document rather than the same bytes. A flat file could not answer the questions actually asked of this data — which chats cost the most this week, what the cache hit rate is per model, which requests failed and how long they hung first — and each of them is now one `SELECT`. The row is opened before the request goes out and filled in as it comes back, so a request that timed out has a row saying so; the CSV had none, since it was only ever written from a successful response's usage block. `conversation_id` and `request_id` name the exchange directory, so a row that looks wrong leads straight to the bodies behind it. Writes go out on a background thread and are dropped rather than queued when the server is unreachable, so a database that is down costs a line in `idea.log` and never a turn. **An existing `model-usage.csv` is left where it is and is no longer appended to**
- Conversation compaction: past 60% of the configured **Context window**, the output of the oldest tool calls is replaced with a one-line note saying which tool produced it and how big it was, until the conversation is back to about 40%. Tool output is what a long chat is mostly made of — a single `read_project_file` is tens of kilobytes and is re-sent with every later turn — so this is what stops one growing until the provider refuses it. The `tool_use` block that asked for it is kept, arguments and all, and the last few calls are never touched, so the model can still see what it did and is still holding what it is working from. Nothing you or the model wrote is ever dropped, and the chat window keeps showing the full output regardless; it is the copy sent with each request that shrinks. Set the context window to 0 to switch it off
- Git tools: a **Version control** group holding `git_status`, `git_diff`, `git_log` and `git_blame`. They go through the IDE's own Git integration rather than the terminal, so they need no approval dialog, return an exit code and output as data instead of scraped terminal text, and — for `git_status` — read the same change list the Local Changes view shows, so the model and the user see one answer. Off by default, like every other non-reading group. Read-only: nothing here commits, checks out or touches a remote
- Tool selection: Settings | Tools | AICodingAgent has a **Select Tools** button opening a picker that lists the built-in tools by category, with a tick-the-whole-group box on each and Read-Only Defaults / Select All / Clear presets. Only the ticked tools are sent. A tool that is off cannot be called, so this bounds what the model may do as well as what the request costs. Defaults to reading and navigation only — editing, running and debugging are switched on when wanted. **Existing setups get the new default**, so re-tick what you need after upgrading
- Prompt caching: the tool definitions and system prompt are marked as a cacheable prefix, and the tail of the conversation is marked as it grows, so a turn that runs several tool-call iterations stops re-reading the whole request each time. Token usage, including cache reads and writes, is logged per request
- Skills: directories listed under Settings | Tools | AICodingAgent are scanned for `SKILL.md` files, and each skill's `name` and `description` are added to the system prompt so the model knows what is available without paying for the instructions until it uses one. Defaults to `.claude/skills`, `.skills`, and `~/.claude/skills`; a path outside the project is allowed
- MCP support: servers configured under Settings | Tools | AICodingAgent have their tools offered to the model alongside the built-in ones, over stdio (local process) or Streamable HTTP (remote). Each call is shown for approval, as shell commands are
- Chat history: conversations are saved per project, reopened from the tool window's history button, and the last one is restored when the IDE restarts
- Initial scaffold created from [IntelliJ Platform Plugin Template](https://github.com/JetBrains/intellij-platform-plugin-template)
